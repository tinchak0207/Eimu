# 总体 PRD 独立审阅

审阅对象：`reports/Eimu 本地 Agent 总体 PRD.md`，v1.0，2026-11-25。审阅者：codex_prd_research；作者为另一代理 write_local_prd。本轮只读 PRD 与既有研究，未运行产品、未修改 PRD。以下是可导致实现偏差的 4 个具体问题，不宣称功能已经验证。

## 1. [P1] 已付费未交付结果可能按 7 天 TTL 永久消失

位置：185 行；137 行 R18；176 行。

反例：用户生成成功、账单已结，但设备关机 8 天。供应商 URL 在 24 小时到期，自有中转在第 7 天删除。重启后订单和哈希还在，实际字节两边都没有。R18 承诺按原订单恢复交付且不重买，在此状态无法满足。提示期限本身不能证明已履行交付。

最小修改：未 ACK 的**唯一可恢复结果副本**不得仅因 TTL 自动删除；到期先确认供应商仍有可取副本、已迁入经授权备份，或进入明确的未交付售后/退款流程。TTL 适用于可替代缓存；将“最后副本删除”与 delivery/settlement 状态绑定。无需改成长久云作品仓，但必须写明孤立订单如何结案。

## 2. [P1] 余额和订阅校验没有区分新消费与旧订单履约

位置：93 行、138 行 R19；167—169 行接口；153 行。

反例：用户余额恰好够买一条视频，提交后归零，下载前断网。R19 的“每请求验证…余额”若被实现成统一前置门，则 query/fetch/ACK 因余额不足被拒；订阅到期也可能阻断已付费结果恢复。用户没有新购买，却必须充值才能取回作品。

最小修改：明确新推理/新生成检查预算和消费资格；已登记订单的查询、对账、下载、ACK、退款及账单查看只检查相应 owner、有效身份与安全撤销规则，不要求当前余额或有效订阅。凭证撤销需重新认证可以阻断访问，但不得抹去履约义务。

## 3. [P1] 租约没有 fencing 规则，网络分区后可能两台设备续跑

位置：99 行；142 行 R23；157 行；225 行。

反例：A 获取执行租约后断网，继续本地后期；租约过期后 B 接管同一任务。A 醒来持旧 task generation 发出新的云生成或写回工程，而 B 已经继续。现有文字说明不双跑、恢复核对，但没有要求云端拒绝旧宿主的操作，也没有定义离线本地修改如何并入。

最小修改：为跨宿主接管增加服务端单调 fencing epoch，云提交及共享工程提交必须携带并验证当前 epoch；旧宿主恢复先核租约，失效则停止自动推进。离线已完成修改保存在独立派生版本，不能覆盖新主版本。若首轮不支持接管，就明确“只遥控原宿主，迁机须安全停机交接”，不把租约过期本身视为安全接管证据。

## 4. [P1] M1 真首作与 M2 才验恢复安全之间缺少外部副作用前闸

位置：116 行 P0 口径；220—221 行阶段表；252 行验收条件。

反例：团队按阶段实现，M1 对真实素材跑付费完整首作，重复扣费/断网恢复/串号/沙箱失败的验收排到 M2。M1 的供应商提交一旦超时，就已经触及尚未验收的 P0 安全语义。252 行把 A01/A02/A09 合并要求，阶段表却允许 M1 在 A02 未覆盖时交付进入下一阶段。

最小修改：M1 首次真实外部副作用前，先满足最小授权/隔离、operation 耐久登记、未知对账、不重复结算与账号隔离；M1 退出条件包含 A01+A02+A09 和相应身份/收费反例。M2 扩大设备故障、负载和媒体种类覆盖，不承担第一次验证资金安全。无需增加测试脚本，只调整阶段验收依赖。
