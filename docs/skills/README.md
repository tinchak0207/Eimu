# 技能文档标准（docs/skills/）

本目录是本项目技能文档的唯一权威目录。每个技能一份 `<name>.md`，由两部分组成：**YAML frontmatter 契约** + **固定正文骨架**。agent 加载技能时先读 frontmatter 决定「能不能用、何时触发、允许调哪些工具」，正文提供工作流细节。

吞并外部 skill（如 shuohao-skills）时，外部能力必须按本标准落档，成为平台的一条「配方」或一个技能——外部 SKILL.md 不直接进库。

## frontmatter 契约（七字段全部必含，缺一即不合格）

| 字段 | 类型 | 约束 |
|------|------|------|
| `name` | string | kebab-case；全目录唯一；必须与文件名（去 `.md`）一致 |
| `version` | string | semver（MAJOR.MINOR.PATCH）。行为契约（工具签名、门禁、输出字段）变更必须升版本 |
| `description` | string | 一句话（≤80 字），说清技能**产出什么**，不写实现细节 |
| `allowed-tools` | string[] | 本技能工作流允许 agent 调用的工具名白名单；未列出的工具不得在该技能流程中使用（防止技能夹带越权工具面） |
| `triggers` | string[] | 触发条件：用户意图描述，命中任一条即加载本技能。写用户会怎么说，不写内部状态 |
| `requires` | string[] | 硬依赖清单（模块路径 / API 端点 / owner 文件）。任一缺失时技能**不可用**，且必须在「失败与降级」声明对应行为 |
| `optional` | string[] | 软依赖清单。缺失时技能降级运行（跳过增强项），不得报错中断；可为空数组 `[]`，但字段本身必须存在 |

frontmatter 示例：

```yaml
---
name: drama-recipe
version: 1.0.0
description: 小说→短剧五段管线配方，五段 JSON 接力，出图走平台生成队列
allowed-tools:
  - lora_search
  - generate_image
triggers:
  - 用户要把小说/文本改编成短剧
requires:
  - src/lib/character-cards.ts
optional: []
---
```

## 正文骨架（四个章节，按序）

1. **`## 用途`**：谁、在创作流程的哪个阶段、用它产出什么。一段话说清，不铺功能清单。
2. **`## 工具契约`**：表格，每个工具一行——`工具 | 入参 | 出参 | 后端 owner`。owner 必须指向真实存在的端点或模块路径，禁止「新建一套」。
3. **`## 行为规则`**：编号铁律。写「必须/禁止」级别的约束，可执行的判定标准，不写建议。
4. **`## 失败与降级`**：结构化错误码 + 每种失败「阻断什么、不阻断什么」。没有降级路径的失败不允许出现。

骨架之外允许追加章节（如字段契约表、管线图、确定性边界），但四个必选章节不得删并、不得换序。

## 写作规则

- 文案一律简体中文。
- 字段契约表统一格式：`字段 | 类型 | 约束`；约束里写默认值、上限、缺失行为。
- 涉及资产 id 时必须指明唯一来源（如 character-cards 卡 id），禁止技能自定义第二套 id 体系。
- 「能算的不让模型猜」：凡可由代码确定性推导的值（秒数、切分、清单求和），文档必须写明由哪个纯函数推导（模块路径 + 函数名），模型层禁止产出该字段。
- 与 generation-gates 的关系：技能文档只**声明**各段跑哪些门（门 id + 判定标准），门的执行归 generation-gates，技能不自带第二套门。
