# PRD：團隊席位（Emu 團隊版）

狀態：草案 v1（2026-10-01）｜決策人：暴君｜**定價＝我（agent）的推薦值，已落在唯一真源，一格可覆蓋**｜約束：**未接線一律拒單，絕不以未履約訂單收款**

---

## 0. 一句話

一個團隊買 N 個席位，每個席位每個週期帶固定的金幣額度，買完由主帳把額度分給成員——**席位是「按人頭買額度」的批發價，不是新權益**。

## 1. 為什麼是這個（第一性）

| 類型 | 內容 |
|---|---|
| FACT | 現場已有兩個端點：`POST /v1/team/seats/order`（報價＋待支付訂單語義）與 `POST /v1/team/seats/allocate`（席位↔配額分配，唯一通路 `member-quota.ts`）。 |
| FACT | 配額的真相只在 new-api `users.quota`：主帳扣、成員加、先扣後加失敗回滾、團隊鎖串行化。**我方不寫任何本地點數**（禁影子帳本）。 |
| FACT | `allocate` 的 `per_seat_coins` 目前是呼叫方自由傳入——**「一個席位該含多少幣」這件事今天在代碼裡沒有定義**，這就是本 PRD 存在的理由。 |
| FACT | 下單端今天回 501 `seat_order_fulfillment_unwired`（`payable:false`）：報價與待支付訂單都算得出來，但**刻意不發起收款**。 |
| INFERENCE | 團隊客戶的採購邏輯是「預算 ÷ 人頭」，不是「一張圖多少錢」；因此單位必須是**席位×週期**，與 B 端密鑰檔位（`tier-pricing.ts` 的每張圖幣價覆寫）是兩個維度，不可共用。 |
| HYPOTHESIS | 團隊願意為「集中出資＋集中分配」付一個高於散買的**管理費**是一個誤判——散買的同量金幣零售價才是錨點，席位價必須低於它。整個定價表按這條推。 |

## 2. 定價（我的推薦，可整表覆蓋）

底價錨點＝零售幣價 **¥0.099/幣**（`plans.ts` 入門包 9.9 元 / 100 幣）。席位履約物是**配額**（金幣），不是金幣之外的新權益 ⇒ 席位單價必須低於同量零售幣價才賣得動，故按**批發折扣**定價：

| 檔位 | 每席位每週期含幣 | 月度 | 季度（×3×0.90） | 年度（×12×0.80） | 每幣實付 |
|---|---|---|---|---|---|
| 轻量档 starter | 300 幣 | **¥27** | **¥73** | **¥259** | 0.090 → 0.072 |
| 团队档 team | 1,000 幣 | **¥85** | **¥230** | **¥816** | 0.085 → 0.068 |
| 旗舰档 flagship | 3,000 幣 | **¥240** | **¥648** | **¥2304** | 0.080 → 0.064 |

- 唯一真源：`src/lib/team-seat-pricing.ts` 的 `TEAM_SEAT_PRICING`（九格）。報價、下單、文案全部自動跟隨，改價只改這一個物件。
- **含幣額（上表第二欄）是本 PRD 新增的定義**：分配時的 `per_seat_coins` 上限＝所購檔位的含幣額，主帳不得超額劃出（否則主帳可以把沒買的額度分給成員）。
- 未配置（null）= 回 `price_not_configured`，**絕不當成 0 元**（0 元成立訂單 = 誠實性事故）。

## 3. 用戶與場景

- **主**：3–20 人的工作室／MCN／設計外包團隊，有一個集中付費的主帳，成員各自用密鑰出圖。
- **次**：需要按人頭報帳的企業試點（採購走對公流程，要一張金額明確的訂單）。
- **不做**：個人用戶（個人走 `plans.ts` 的金幣包）；跨團隊轉讓席位；成員自行買席位。

## 4. 流程

```
POST /v1/team/seats/order {tier, cycle, seats}        ← 只有 owner 可下單（403 擋成員）
  └ 報價 ＝ TEAM_SEAT_PRICING[tier][cycle] × seats（同源價表，客戶端傳價一律不參與計價）
      └ 產出待支付訂單：out_trade_no ＝ TS+sha256(team:tier:cycle:seats)[:16]
                       param        ＝ seat:<team>:<tier>:<cycle>:<seats>
          └ 【收銀台】mapay checkout 帶 seat: param 發起收款   ← 今天缺這一跳
              └ mapay 回調 /api/payments/mapay/notify
                  ├ 用 quoteSeatOrder 重算總價，與回調 money 比對（不對 → 400，不履約不收錢）
                  └ 走「席位履約」分支（**不得**走 fulfillMapayRedemption，那條發金幣兌換碼）
                      └ 寫入席位意圖（該團隊：檔位 × 週期 × 席數 → 含幣額）
                          └ 主帳配額 → 按席位分配，唯一通路 allocateMemberQuota
                              └ POST /v1/team/seats/allocate {member_user_id, seats, per_seat_coins}
                                  └ 目標額度 ＝ seats × per_seat_coins（絕對目標值 ⇒ 天然冪等）
```

三個不可動的性質：

1. **冪等**：`out_trade_no` 只由請求四元組決定性推導（無時間、無隨機）⇒ 同請求重放永遠是同一張訂單，不會產生第二筆。
2. **金額只由我方價表決定**：客戶端傳來的 price/money 一律不參與計價；回調金額與 `quoteSeatOrder` 重算值不符 → 拒。
3. **無影子帳本**：我方不落本地點數；配額真相只在 new-api。

## 5. 誠實性硬閘（違反 = 事故）

- **未接線不得收款**：履約分支（下表 1、2 條）落地前，下單端保持 501 `payable:false`，且**刻意不提供「翻一個布林就能收款」的旋鈕**（那會讓收錢不履約變成一行 diff）。
- **收錢不履約的具體機制已在現場踩到**：既有 checkout 只認 `plans.ts` 的套餐 id；若把席位訂單硬塞進去，notify 端 `resolvePricingPlan(param)` 必然 null ⇒ 對 mapay 回 400 ⇒ 錢收了、服務沒給。所以必須先加 `seat:` 分支。
- **續費必須帶期別判別碼**：訂單 id 只由四元組決定，同規格續費會與上次重合（今天不支援續費，寧缺勿錯）。
- **退款需對稱回收**：降目標額度 + 席位回退，走同一條 `allocateMemberQuota`（禁止只加不回）。

## 6. 落地清單（三條，現場檔內已列）

| # | 做什麼 | 動哪 |
|---|---|---|
| 1 | notify 對 `param` 以 `seat:` 開頭者走席位履約分支（加席位意圖＋配額分配），不得誤走 `fulfillMapayRedemption` | `src/app/api/payments/mapay/notify/route.ts` |
| 2 | notify 用 `quoteSeatOrder`（同源價表）重算總價，與回調 money 比對（沿用 `mapayMoneyAcceptable`） | 同上 |
| 3 | 收銀台入口：讓席位訂單能帶著 `seat:` param 發起收款（既有 `buildMapayCheckoutFields` 一簽名就是真收款，缺的是可複用的建單入口） | `src/app/api/payments/mapay/checkout/route.ts` |

## 7. 指標

| 環節 | 指標 | 目標 |
|---|---|---|
| 通 | `POST /v1/team/seats/order` 從 501 轉為可支付 | 1 筆真成交入帳 |
| 履約 | 支付成功 → 團隊配額增加 | 金額 = quote 重算值，誤差 0 |
| 分配 | 主帳 → 成員桶目標額度 | 成員桶讀數 = seats × per_seat_coins |
| 誠實 | 金額不符／未配置價／非 owner | 三條各回 400 / 409 / 403，且**不產生任何配額變動** |

北極星：**已履約收入的席位數**。

## 8. 分期

| 期 | 內容 | 過關判準 |
|---|---|---|
| 1（本 PRD） | 定價落地（已做）＋ 收銀台入口 ＋ notify 席位分支 ＋ 金額覆核 | **一筆真席位成交入帳**，配額 delta 與報價重算值一致 |
| 2 | 續費（期別判別碼）、退款對稱回收、席位回收面板 | 續費不與首購訂單撞 id |
| 3 | 席位使用看板（每人已用/剩餘）、超額提醒 | 依第 1 期真實數據決定 |

## 9. 複用（不造輪子）

- 計價：`team-seat-pricing.ts`（單一價表，禁抄第二份數字）
- 冪等：sha256 決定性 id（照 `member-quota` 的「絕對目標值天然冪等」思路）
- 分配：`member-quota.ts` 的 `allocateMemberQuota`（唯一通路）
- 支付：mapay 既有簽名與回調覆核（`formatMapayMoney` / `mapayMoneyAcceptable` / `createMapayOrderId` 同族）

## 10. 不做（本期）

- 不改個人用戶價目、不動新人禮與首充卡
- 不做席位續費與退款（缺期別判別碼，見 §5）
- 不做 member 自助買席位（只有 owner 可下單）
- 不做席位之外的團隊權益（席位＝按人頭買額度，不附新功能）

## 11. 待暴君拍板

2. **含幣額**（300 / 1,000 / 3,000 幣/席位/月）：這是新定義，直接決定「一個席位值多少」——比單價更關鍵。
