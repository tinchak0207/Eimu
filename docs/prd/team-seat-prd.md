# PRD：团队席位（Emu 团队版）

状态：草案 v1（2026-10-01）｜决策人：暴君｜**定价＝我（agent）的推荐值，已落在唯一真源，一格可覆盖**｜约束：**未接线一律拒单，绝不以未履约订单收款**

---

## 0. 一句话

一个团队买 N 个席位，每个席位每个周期带固定的金币额度，买完由主帐把额度分给成员——**席位是「按人头买额度」的批发价，不是新权益**。

## 1. 为什么是这个（第一性）

| 类型 | 内容 |
|---|---|
| FACT | 现场已有两个端点：`POST /v1/team/seats/order`（报价＋待支付订单语义）与 `POST /v1/team/seats/allocate`（席位↔配额分配，唯一通路 `member-quota.ts`）。 |
| FACT | 配额的真相只在 new-api `users.quota`：主帐扣、成员加、先扣后加失败回滚、团队锁串行化。**我方不写任何本地点数**（禁影子帐本）。 |
| FACT | `allocate` 的 `per_seat_coins` 目前是呼叫方自由传入——**「一个席位该含多少币」这件事今天在代码里没有定义**，这就是本 PRD 存在的理由。 |
| FACT | 下单端今天回 501 `seat_order_fulfillment_unwired`（`payable:false`）：报价与待支付订单都算得出来，但**刻意不发起收款**。 |
| INFERENCE | 团队客户的采购逻辑是「预算 ÷ 人头」，不是「一张图多少钱」；因此单位必须是**席位×周期**，与 B 端密钥档位（`tier-pricing.ts` 的每张图币价覆写）是两个维度，不可共用。 |
| HYPOTHESIS | 团队愿意为「集中出资＋集中分配」付一个高于散买的**管理费**是一个误判——散买的同量金币零售价才是锚点，席位价必须低于它。整个定价表按这条推。 |

## 2. 定价（我的推荐，可整表覆盖）

底价锚点＝零售币价 **¥0.099/币**（`plans.ts` 入门包 9.9 元 / 100 币）。席位履约物是**配额**（金币），不是金币之外的新权益 ⇒ 席位单价必须低于同量零售币价才卖得动，故按**批发折扣**定价：

| 档位 | 每席位每周期含币 | 月度 | 季度（×3×0.90） | 年度（×12×0.80） | 每币实付 |
|---|---|---|---|---|---|
| 轻量档 starter | 300 币 | **¥27** | **¥73** | **¥259** | 0.090 → 0.072 |
| 团队档 team | 1,000 币 | **¥85** | **¥230** | **¥816** | 0.085 → 0.068 |
| 旗舰档 flagship | 3,000 币 | **¥240** | **¥648** | **¥2304** | 0.080 → 0.064 |

- 唯一真源：`src/lib/team-seat-pricing.ts` 的 `TEAM_SEAT_PRICING`（九格）。报价、下单、文案全部自动跟随，改价只改这一个物件。
- **含币额（上表第二栏）是本 PRD 新增的定义**：分配时的 `per_seat_coins` 上限＝所购档位的含币额，主帐不得超额划出（否则主帐可以把没买的额度分给成员）。
- 未配置（null）= 回 `price_not_configured`，**绝不当成 0 元**（0 元成立订单 = 诚实性事故）。

## 3. 用户与场景

- **主**：3–20 人的工作室／MCN／设计外包团队，有一个集中付费的主帐，成员各自用密钥出图。
- **次**：需要按人头报帐的企业试点（采购走对公流程，要一张金额明确的订单）。
- **不做**：个人用户（个人走 `plans.ts` 的金币包）；跨团队转让席位；成员自行买席位。

## 4. 流程

```
POST /v1/team/seats/order {tier, cycle, seats}        ← 只有 owner 可下单（403 挡成员）
  └ 报价 ＝ TEAM_SEAT_PRICING[tier][cycle] × seats（同源价表，客户端传价一律不参与计价）
      └ 产出待支付订单：out_trade_no ＝ TS+sha256(team:tier:cycle:seats)[:16]
                       param        ＝ seat:<team>:<tier>:<cycle>:<seats>
          └ 【收银台】mapay checkout 带 seat: param 发起收款   ← 今天缺这一跳
              └ mapay 回调 /api/payments/mapay/notify
                  ├ 用 quoteSeatOrder 重算总价，与回调 money 比对（不对 → 400，不履约不收钱）
                  └ 走「席位履约」分支（**不得**走 fulfillMapayRedemption，那条发金币兑换码）
                      └ 写入席位意图（该团队：档位 × 周期 × 席数 → 含币额）
                          └ 主帐配额 → 按席位分配，唯一通路 allocateMemberQuota
                              └ POST /v1/team/seats/allocate {member_user_id, seats, per_seat_coins}
                                  └ 目标额度 ＝ seats × per_seat_coins（绝对目标值 ⇒ 天然幂等）
```

三个不可动的性质：

1. **幂等**：`out_trade_no` 只由请求四元组决定性推导（无时间、无随机）⇒ 同请求重放永远是同一张订单，不会产生第二笔。
2. **金额只由我方价表决定**：客户端传来的 price/money 一律不参与计价；回调金额与 `quoteSeatOrder` 重算值不符 → 拒。
3. **无影子帐本**：我方不落本地点数；配额真相只在 new-api。

## 5. 诚实性硬闸（违反 = 事故）

- **未接线不得收款**：履约分支（下表 1、2 条）落地前，下单端保持 501 `payable:false`，且**刻意不提供「翻一个布林就能收款」的旋钮**（那会让收钱不履约变成一行 diff）。
- **收钱不履约的具体机制已在现场踩到**：既有 checkout 只认 `plans.ts` 的套餐 id；若把席位订单硬塞进去，notify 端 `resolvePricingPlan(param)` 必然 null ⇒ 对 mapay 回 400 ⇒ 钱收了、服务没给。所以必须先加 `seat:` 分支。
- **续费必须带期别判别码**：订单 id 只由四元组决定，同规格续费会与上次重合（今天不支援续费，宁缺勿错）。
- **退款需对称回收**：降目标额度 + 席位回退，走同一条 `allocateMemberQuota`（禁止只加不回）。

## 6. 落地清单（三条，现场档内已列）

| # | 做什么 | 动哪 |
|---|---|---|
| 1 | notify 对 `param` 以 `seat:` 开头者走席位履约分支（加席位意图＋配额分配），不得误走 `fulfillMapayRedemption` | `src/app/api/payments/mapay/notify/route.ts` |
| 2 | notify 用 `quoteSeatOrder`（同源价表）重算总价，与回调 money 比对（沿用 `mapayMoneyAcceptable`） | 同上 |
| 3 | 收银台入口：让席位订单能带著 `seat:` param 发起收款（既有 `buildMapayCheckoutFields` 一签名就是真收款，缺的是可复用的建单入口） | `src/app/api/payments/mapay/checkout/route.ts` |

## 7. 指标

| 环节 | 指标 | 目标 |
|---|---|---|
| 通 | `POST /v1/team/seats/order` 从 501 转为可支付 | 1 笔真成交入帐 |
| 履约 | 支付成功 → 团队配额增加 | 金额 = quote 重算值，误差 0 |
| 分配 | 主帐 → 成员桶目标额度 | 成员桶读数 = seats × per_seat_coins |
| 诚实 | 金额不符／未配置价／非 owner | 三条各回 400 / 409 / 403，且**不产生任何配额变动** |

北极星：**已履约收入的席位数**。

## 8. 分期

| 期 | 内容 | 过关判准 |
|---|---|---|
| 1（本 PRD） | 定价落地（已做）＋ 收银台入口 ＋ notify 席位分支 ＋ 金额覆核 | **一笔真席位成交入帐**，配额 delta 与报价重算值一致 |
| 2 | 续费（期别判别码）、退款对称回收、席位回收面板 | 续费不与首购订单撞 id |
| 3 | 席位使用看板（每人已用/剩余）、超额提醒 | 依第 1 期真实数据决定 |

## 9. 复用（不造轮子）

- 计价：`team-seat-pricing.ts`（单一价表，禁抄第二份数字）
- 幂等：sha256 决定性 id（照 `member-quota` 的「绝对目标值天然幂等」思路）
- 分配：`member-quota.ts` 的 `allocateMemberQuota`（唯一通路）
- 支付：mapay 既有签名与回调覆核（`formatMapayMoney` / `mapayMoneyAcceptable` / `createMapayOrderId` 同族）

## 10. 不做（本期）

- 不改个人用户价目、不动新人礼与首充卡
- 不做席位续费与退款（缺期别判别码，见 §5）
- 不做 member 自助买席位（只有 owner 可下单）
- 不做席位之外的团队权益（席位＝按人头买额度，不附新功能）
