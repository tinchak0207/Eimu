补充说明：

- 目标验收的 nudge 复用既有 `prompt_async` 通道，不新写模型客户端；派遣复用
  `subagent.runGoalEvaluator`（与 machine critic 同一套 `dispatchAttempt` / modelChain / 超时 / 心跳）。
- `not_met` 会经 `recordVerdict` 落库（该函数把目标置为终态），因此「连续 3 次」计数是
  防御性上限；同一目标被重新 propose/approve 时按新 goal id 重新计数。
- 权限闸对「未配置任何策略」的 `default` 模式兜底 ask 刻意放行给既有 guard：
  否则网关进程内新建的 policy state 会把全部非只读工具判 ask，插件又没有确认队列，
  等于让运行时整体瘫痪。显式 deny/ask 规则、safetyCheck、其它模式仍按裁决执行。

## 4. 未移植清单与理由

| 项 | 理由 |
| --- | --- |
| worktree（独立 git worktree 沙箱） | opencode 运行时没有 CC 的 worktree 生命周期与 tool 上下文；Eimu 的隔离由 bwrap + 会话目录承担。强行嫁接会绕过现有路径闸。 |
| Chrome / 浏览器自动化 | Eimu 生产没有受控 Chrome 会话；`read_image` / `vision_analyze` 已覆盖视觉感知。引入浏览器等于新增高权限执行面。 |
| RemoteTrigger（远端触发器） | 需要 CC 的托管调度服务；Eimu 已有 loopback cron/wakeup，远端入口会扩大攻击面。 |
| 插件市场 / 插件安装 | opencode 插件是本地 `.opencode/plugin/*.ts`，没有市场运行时；动态安装 = 任意代码执行，未纳入。 |
| deferred tool loading | opencode 的 tool 注册在前端一次完成，没有 CC 的 tool search / 延迟加载 API；只能在 prompt 层做公告裁剪（见 `prompt-registry.ts`），不能真实延迟注册。 |
| CC 的 checkpoint / rewind | Eimu 已有子代理 checkpoint 与 workflow_rollback，语义不同源；本轮不改既有回滚链。 |
| deny 审计补 `reason.type/source/rule` | 现有 `appendDenyAudit` 消费的是 opencode 拒绝消息推导出的 `DenyProvenance`，而 `toDenyAuditRecord` 只接受 `PermissionDecision`。两者不是同一来源，直接替换会把「规则层拒绝」误记成「权限内核拒绝」。本轮不改 `events-translate.ts` 审计形状，留待权限闸自己也产生 deny 时再统一。 |
| 跨进程确认队列 | 插件进程没有 opencode 的 confirm 队列句柄；`ask` 只能 fail-closed。要支持确认需在插件与 gateway 之间新增长轮询协议，超出「最薄一层」范围。 |

## 6. 验收判据（真路径 + Hacker）

### 6.1 真路径（必须有一条完整用户路径证据）

1. **任务板**：新建会话 → 让 orchestrator 调 `task_create` → `task_list` 可见 →
   `task_update` 设 owner 后 `mailbox_read`（owner 侧）收到 `task_assignment` 帧。
2. **目标验收**：`propose_goal` → `goal/approve` → 完成一回合 → 日志出现
   `goal evaluator dispatched` → `goal/status` 看到 `verdict` 与 `reason`。
3. **计划模式**：`enter_plan_mode` → 调 `bash` 被插件拒绝（返回「计划模式」中文错误）→
   `exit_plan_mode` 走既有 confirm 卡批准 → 再调 `bash` 放行。
4. **cron/wakeup/monitor**：`cron_create` 一分钟后触发 → 会话空闲时被唤醒；
   `monitor_watch` 起一个短命令 → `monitor/status` 有输出；`schedule_wakeup` 到点唤醒。
5. **artifact/memory/findings**：`artifact_publish` 一个文件 → `artifact_get/verify` 回读 sha256；
   `memory_save` → `memory_list/read` 可见；`report_findings` 一批 → `findings/list` 条数一致。
6. **权限**：`permission/rules` 设一条 `deny` 规则 → 对应工具调用被插件拒绝；
   删除规则后放行。

禁止把「HTTP 200」「工具文件存在」「bun build 通过」当作验收完成——它们只是变更探针。

### 6.2 Hacker（作者 ≠ Hacker）

由另一个 agent 或人工以弄坏它为目标，至少覆盖：

- 空 body / 非 JSON / 超长字段 / 非法 taskId / 不存在 session；
- cron 非法 5 字段、过去时间、durable 状态文件损坏；
- artifact 符号链接、>16MiB、sha256 变更、并发 expected_version；
- plan 文件超 2MB、路径逃逸、confirm 超时；
- 权限规则大小写、symlink realpath、`dangerouslyDisableSandbox`；
- 目标验收：验收者输出非 JSON / 空正文 / 连续 not_met / 并发上限满；
- 网关不可达时插件仍按既有 guard 工作（不整站瘫痪）。

验收结论必须写明：oracle 是哪条真路径、Hacker 是谁。写不出来 = 未验。

### 8.2 仍属信任边界（未在本轮解决，不得当作已修）

- **hook 上下文未接线**：`harness-hooks.ts` 产出 `additionalContext`，但它的注入端不在本轮可改范围；
  本轮只提供并导出 `fenceInjectedData`，接入时必须先过该函式，否则 hook 文本仍可能伪造章节。
- **persona 模型不受 latch**：风格行按 session latch，但 `personaModel(state)` 仍每轮取实时设置
  （换模型是用户明确意图）；两者在切换后的一轮内可能短暂不一致，压缩/失效后收敛。
- **tail 优先级由追加顺序决定**：`enforceTurnTailBudget` 从最后 part 起截断；若未来有新的必保
  tail 注入，必须放在前面，否则会被先裁。beast 手册体积暴增到超过总预算时，截断只保证总额，
  不保证手册完整（应优先调大 `PROMPT_TOTAL_BUDGET_CHARS`，而不是依赖静默裁剪）。
- **模型窗口映射是启发式**：未列入 `MODEL_WINDOW_RULES` 的模型不显示 token 提醒；
  新增模型需补规则，不能靠猜。
- **附件围栏只覆盖 `[ATTACHMENTS_BLOCK]`**：块外正文仍是用户原文（仅过 `sanitizeUserContent`），
  用户自己的文件路径不会自动围栏化。
- **artifact_register 与 artifact_publish 仍是两套存储**：互指只统一了描述与契约，
  未合并数据面。
- **验收边界**：本轮证据是渲染脚本 + `bun build index.ts` + 26 个工具 `bun build`；
  没有生产真路径调用，按 §6.1 只能算变更探针，不能宣称生产可用。
