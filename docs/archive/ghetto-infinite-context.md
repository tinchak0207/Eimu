# 土炮无限上下文 —— 一套开发 Harness 的方法论与演进史

> 来源：2026-06 ~ 2026-09 期间，用 AI agent 全程开发一个生产级图像/视频生成平台的过程中，沉淀出的开发 harness 方法论。已脱敏：不含任何密钥、域名、渠道与供应商信息。
>
> 结论先行：**上下文窗口是缓存，不是真相源。「无限上下文」的正确实现不是更大的窗口，而是「状态外置 + 索引按需取回 + 规则化写入纪律」。** 这套东西不需要新模型，任何 agent + 一套纪律就能跑。

---

## 一、核心命题

模型上下文窗口有三个天生缺陷：装不下（长任务超窗）、留不住（会话结束即失忆）、不可信（压缩摘要会丢细节，模型会脑补丢失的部分）。

主流解法有两条路：

- **扩窗口**：更大窗口、稀疏注意力、滚动 KV 缓存——成本高，且「留不住、不可信」两个缺陷原样保留。
- **外置化**：把真相写到窗口外面（持久记忆、数据库、状态机），窗口里只放索引和当前工作集，需要时按需取回。

第二条路就是「土炮无限上下文」。GPT-6 Astra（2026-09-03 发布）官方描述的机制——「不再单纯依靠压缩总结保存历史，而是可以跨上下文窗口保存笔记，并可搜索此前的消息和工具输出找回需求、测试结果和修改记录」——本质就是这条路。区别仅在于：它被训练进了模型运行时，由模型自主决定记什么、搜什么；而土炮版本由工程规则强制执行。

## 二、七大机制（每条都由真实事故催生）

### 1. 持久记忆层：「不写 = 智力归零」

- **做法**：一个 notes 目录，一事一档（文件名带日期与主题）；外加一份总纲索引文件，每条记忆一行摘要。
- **写入纪律**：每完成一个可用工具、解决一个反复出现的问题、被纠正一次——当场写，不等任务结束。
- **催生事故**：同一类坑反复踩（同一个 patch 打错文件三次、同一个「必须重启服务才生效」三次实锤）。没有记忆，每个会话都是从零开始的考古。

### 2. 记忆分层：常驻的只有索引

- **做法**：索引文件常驻每次会话（每条一行 hook）；正文按需再读。规则文件只加行为规则，排障笔记进 runbook，历史归 memory（「膨胀铁律」）。
- **原理**：常驻上下文是稀缺资源，只放「决定要不要深入读」的信息，不放信息本身。
- **催生事故**：规则文件膨胀到 37.5KB，常驻开销吃掉大半有效上下文，一次瘦身砍掉 70% 常驻量，能力零损失。

### 3. 记忆注入契约：索引独占者必须点名

- **做法**：派发子任务（subagent）时，任务书必须包含「必读记忆」节：总纲路径 + 2-5 个与任务直接相关的记忆档名（各附一句为何相关）+ 一条仲裁指令「记忆与现场证据冲突时，以现场为准并回报冲突」。缺这一节 = 禁止派发。
- **催生事故**：子代理被派去盘点资产，任务书只写了 grep 目标，没给任何记忆指针——子代理把记忆里明确标注「仍被引用、是活的」的组件当废物误判，重复考古。根因：记忆索引只有 orchestrator 独占，不点名注入 = 恶性引导。

### 4. 状态机外置：断点续跑的真相不在对话里

- **做法**：会话状态、工作流进度、任务队列全部持久化到外部存储（数据库/落盘文件）；对话窗口里只有「指针」。崩溃/重启后按状态机恢复续跑（checkpoint + 回放游标），而不是重放整段对话。
- **催生事故**：长任务中途服务重启，靠重放对话恢复 → 回放游标错位导致整屏空白；僵尸会话误判复活；退款在真相未明时就执行。修完的定论：**「真相未明，永不退款、不重投、不宣判」**——所有终态判定必须以外部持久化证据为准，不以对话里的宣告为准。

### 5. 压缩白名单：砍上行内容必须双向同步

- **做法**：传给 agent 的元数据走白名单压缩（只传必要字段）。每新增一组字段，必须同步加进「对象完整版」和「压缩版」两处白名单，并配一份往返（round-trip）合同测试。
- **催生事故**：上行压缩器把一组状态指针字段砍光，刷新后 agent 拿到空壳元数据报「示意图未同步」；另一处白名单漏字段导致整份存档炸掉。

### 6. 验证诚实契约：不宣称未验证的成功

- **做法**：硬性规则——「配置成功 ≠ 可用，HTTP 200 ≠ 能出图，状态显示完成 ≠ 产物存在」；宣称成功必须带新鲜端到端证据；故意跑预期失败的测试是浪费；验证意外失败先诊断根因再重跑。
- **催生事故**：模型在工具调用被拒后自行编造「已提交成功」收尾；计费显示已扣款而账本零记录；进度条冻结在 44% 的假进度。判别法沉淀为：**假成功的本质是「宣告」与「外部证据」脱钩，所以验证永远只认外部证据。**

### 7. 规则迭代闭环：每次纠正当回合生效

- **做法**：用户每反馈一次「这条规则没生效/浪费时间」，当回合先改规则再继续做事——每个反馈就是一次 harness 压缩迭代。反过来，规则本身也要瘦身：只加行为规则，笔记外移。
- **原理**：harness 不是一次性设计出来的，是把每次事故折旧成一条规则。规则的单位是「禁止/必须 + 为什么（事故指针）」，没有事故支撑的规则会被淘汰。

## 三、演进史（时间线）

| 阶段 | 日期 | 事件 | 沉淀出的机制 |
|---|---|---|---|
| 萌芽 | 06-10 | 最早的规则 note：禁止 agent 自查 UI（慢且越权），视觉验收归用户 | 验证分工；notes 系统开始记录 |
| 雏形 | 07-31 | 「八件套 system harness」概念提出：目标不变性/世界模型/瓶颈治理/复利架构/实验环/证据契约/沟通契约/停止条件 | 方法论有了骨架，「证据契约」沿用至今 |
| 主力期 | 08 中旬 | 全职用 agent 开发生产项目，事故密度陡增 | 记忆写入纪律成型 |
| 轮子事故 | 08-25 | 「精简复制」一个模板轮子，砍掉了触摸事件与物理参数，三轮返工 | 禁造轮子铁律：点名复用 = 逐行复制 + 白名单 diff 验收 |
| 三分法瘦身 | 08-29 | 规则文件 37.5KB → 常驻砍 70%：行为规则常驻、排障进 runbook、历史归 memory | 膨胀铁律；记忆分层正式化 |
| 派遣学成型 | 08-29~31 | subagent 大任务拆片、任务书必带配方 + 时间预算 + 2 倍杀线；「调用 skill = 跑完整流水线」被纠正入档 | subagent 派遣纪律 |
| 记忆注入契约 | 09-02 | 暴君纠正「恶性引导：subagent 一个 memory 都没看」 | 任务书必读记忆节，缺 = 禁派 |
| 诚实化高潮 | 09-01~04 | 断点穿透五物种实测、假成功判别法、对账铁律「真相未明不宣判」、改写 git 历史前必 stash 事故 | 验证诚实契约 + 状态外置终极版 |

演进的规律：**每条规则都不是设计出来的，是某次事故的墓碑。** 方法论的成长速度 = 事故复盘的诚实例度。

## 四、与 GPT-6 Astra 官方方案的映射

| GPT-6 官方说法（发布信息转述） | 土炮对应物 |
|---|---|
| 跨上下文窗口保存笔记 | notes 一事一档 + 当场写入纪律 |
| 可搜索此前的消息和工具输出找回需求/测试结果/修改记录 | 索引常驻 + 正文按需读 + grep 考古 |
| 不再单纯依靠压缩总结 | 压缩白名单双向同步 + 回放游标替代对话重放 |
| 长任务不丢上下文 | 状态机外置 + checkpoint 续跑 |
| 等待用户回复时基于合理假设自主推进 | 三档交互模式 + 非阻塞确认 + 降级路径 |

关键差异：

1. **执行主体**：GPT-6 把这套机制训练进了模型运行时，模型自主决定记什么搜什么；土炮版靠显式规则与任务书契约强制执行。前者覆盖率高但不可审计，后者可审计、可迭代，但依赖纪律执行。
2. **边界**：GPT-6 的机制服务于单一模型实例的记忆连续性；土炮版额外覆盖了多 agent 之间的记忆分发（注入契约）与计费/终态等业务真相的对账。
3. **窗口本身**：传闻中的分层稀疏注意力 + 滚动缓存属于模型内部架构，与 harness 层正交——就算窗口无限大，「留不住（跨会话）」「不可信（压缩脑补）」仍需外置化解决。

## 五、可移植清单：30 分钟搭最小可用版

1. 建一个 `notes/` 目录 + 一个 `SUMMARY.md` 索引（每条一行）。定一条写入纪律：「解决任何会复发的问题/被纠正一次 → 当场写档 + 更新索引」。
2. 在项目规则文件（AGENTS.md/CLAUDE.md 等）里写死四条：①不宣称未验证的成功 ②规则文件只加行为规则 ③子任务书必须注入相关记忆 ④每次纠正当回合改规则。
3. 所有任务状态落盘（哪怕只是一个 JSON 状态文件），恢复时读状态不重放对话。
4. 任何「传给 agent 前先压缩」的白名单，配一份往返测试。
5. 每次事故复盘写一条规则，规则必须带事故指针；一个季度没触发过的规则删掉。

就这么多。剩下的所有复杂性，都是从这五条里长出来的。
