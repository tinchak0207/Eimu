## 3. 导出现在还不能算「能改」

- **FCPXML 不可移植**：
  - 素材 `src` 写的是 `file:///tmp/...` 的绝对路径。临时目录一清，或者换一台机器，素材就失联。
  - 只声明了一个 1080p 格式，套在 1344×768 的素材上。
- **剪映草稿多半打不开（推断，仍需剪映真开一次确认）**：
  - zip 里只有 `draft_content.json` 和素材，没有 `draft_meta_info.json`。
  - `draft_content.json` 顶层只有 6 个键。
  - 素材宽高写成 1920×1080，实际是 1344×768。
  - 字号 8。
  - 到目前为止，没有人在剪映里打开过它。

## 4. 方针

1. **E1 只认真实入口。** 输入是生产会话 API 收到的用户首句原文，工程由 agent 自己建。脚本直连执行器的跑法只能叫「管线冒烟」，同一形态最多 3 次，不计入成片率。
2. **样本由外部给定，不由跑的人挑。** 让执行者自己出题，题会越出越容易，这批句子就是现场例证。
3. **付费授权写明信息目标和次数上限。** 「导出 N 条」这类能自己加一的计数器不准当目标。同一形态跑到第 3 次还没有新失败，就自动停。
4. **堵自签评审：**
   - `signedCriticVerdictOutput` 挪进测试 fixtures，生产模块不再导出；
   - 生产验签拒收 `critic:fixture` 和 `call_fixture`；
   - 生产 `VERDICT_KEY` 必须和测试不同；
   - rubric 必须和媒体类型对得上。
5. **交付闸拿首句硬约束核对产物。** 首句里的「没有字幕」「镜头固定」「时长」逐条和产物比对，写着无字幕却有字幕轨，就判失败。
6. **`submit_unknown` 必须对账收尾。** 按上游任务的最终状态 commit 或 refund，预扣不许永久挂着（`cbb57379` 就是现例）。这对应「没做成不扣」。
7. **导出做到真能在剪辑软件里改：**
   - FCPXML 打成带素材的包，用相对路径；
   - 素材格式按真实宽高，`hasAudio` 按真实音轨写；
   - 剪映草稿照开源实现补齐全部必需文件和字段；
   - 在剪映里真打开一次，才算交付。
8. **品味锚要压得过模型默认审美。** 不压，所有产线都会出成同一种青橙色调。每镜生成后先过一道便宜的视觉检查，看主体在不在画面里，再进下游。画面里需要的字一律走字幕或后期叠加，不让视频模型去画。
9. **声音和分辨率如实报。** 用户要静音，导出时就剥掉音轨；放大到 1080p 的片，要标明原生是 720p。
