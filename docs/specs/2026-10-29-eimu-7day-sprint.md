## 2. 算力账（先算账再派工）

### 2.1 已知（FACT，第三方转述 xAI 定价页，2026-10）

- Ultra 是一个每周共享池，按算力计量，不按条数。额度是 Plus 的 50 倍，xAI **不公开绝对值**，重置时点按账号不同，只能在 usage 页看到。
- grok 4.7 fast 只在 Grok Build / Cursor 里能用，从订阅池里扣，单价是标准价的 2 倍，折算 API 价为：输入 $4/M、缓存 $1/M、输出 $12/M。
- grok 只能当**开发 worker** 用。它不能当 Eimu 的运行时模型。被测 agent 打的是生产底模，现网是 happycoding `deepseek-v4.1-flash`，不是 Sonnet 5.5。那仍是真钱。

### 2.2 假设（HYPOTHESIS，D1 校准）

- 一周的池子折合 API 价约 **$300**（取 $250–500 的中位）。
- 一个编码切片：约 40 轮，累计输入约 2.5M（80% 命中缓存），输出约 60k，**合计约 $4.7**。
- 一个独立 Hack 或验收片约 **$2**。
- **一片约 $6.7，一周池子大约够 45 片。**
- **并发 3–4 路**。订阅侧的速率上限不公开，开到 10 路以上大概率被限流，反而更慢。

### 2.3 D1 校准规则（不靠猜）

1. D1 先跑 3 片。读 usage 页的百分比变化，算出「每 1% 等于几片」。
2. 用这个数重排全周切片数，写回本节。
3. 同时记下周池的重置时点。如果重置落在 D3–D6，冲刺期内就有约 1.5 个池子，切片数按比例上调。
4. **燃烧线**：第 N 天收工时，累计用量 ≤ N/7 × 90%。超线就砍 §2.4 里优先级最低的一行，不降主线判准。

## 3. 终点（D7 可测，五条同时成立才算完）

1. **E1 成片率**：生产 20 条真实首句需求（按 §8.1 分层抽样），无人干预跑到 `export` 且 deliver 检查全过 ≥16/20；暴君抽看 5 条，「愿意发出去」≥3 条。
2. **E2 不迷路**，分两层：
   - **甲层（脚本局，零 LLM 费）**：fake opencode 按脚本回放，加故障注入。120 个场景 × 5 种故障 = **600 局**。伪用户消息 =0，同签名重复扣费 =0，每轮输入 ≤64KB，失败或钉住的节点零丢失。
   - **乙层（真模型局，Sonnet 5.5＋假上游）**：**40 局**，目标漂移 ≤1 局（≤2.5%），无一局重复扣费。
3. **E3 能改**：任一成片「改第 3 镜」只重跑该镜及下游（I6），可一键导出 **剪映草稿 + FCPXML**，在剪映里打开能看到分镜、字幕轨、音轨。
4. **E4 不丢**：关页、重登、网关重启后，工程、进度、产物、账单一样不少（真机按这三步跑一遍）。
5. **E5 激活**：新用户首登就看到一个能跑的「复刻这部片」入口；上线后 72h 里「注册 → 发起」≥50%（基线 21%）。

下限（不可牺牲）：13 条产线配方全部可执行（I7），不许砍产线换成片率；研究和独立评审环节不许为提速删掉。

## 4. 五条主线

### L1 工程图上线（D1–D2，最先做，后面所有事都压在它上面）

- D1：生产 gateway 加开关 `PROJECT_MODE_DEFAULT`，**新会话默认走工程模式**，`creator_legacy` 保留一个版本回滚（J4 默认按此执行）。exec-bridge 的 systemd 单元＋token 首批就落好（§9.1-6）。
- D1：先验 §9.1 的两个未验证风险（opencode 是否用了被原地裁剪的 messages、90 秒长轮询会不会撞看门狗）。不成立就停手，换掉 S15 这一片，不另起第二套。
- D2：orchestrator 亲自执行 20 条 E2E（付费，subagent 不持 key）。失败按根因归类，每一类修一次再重跑**只跑失败的那几条**。
- 退出条件：E1 机器口径 ≥16/20。

### L2 影子用户自我对局（两层；量放在零成本的那层）

- **对局台**：在 `fake-platform` 的基础上扩出两部分（这是暴君点名要的东西，不算自造工具）：
  - **假上游**：按节点类型返回可解码的小样（ffmpeg 色条＋正弦音）。
  - **fake opencode 回放器**：吃一个场景脚本，按脚本吐出工具调用和文本。
  - **可注入的故障**：超时、坏文件、网关中途重启、用户中途改主意、离开再回来。
- **场景脚本**：grok 一次批量写 **120 个**。人设来自生产 `sessions.db` 首句需求的改写和脱敏，加上竞品案例页的需求。每个脚本 5–40 轮，包含中途纠正、钉住、「第 3 镜重拍」。
- **甲层**：120 个脚本 × 5 种故障 = 600 局。纯 CPU，夜里批量跑，跑多少次都不花钱。
- **乙层**：40 局，D2 / D4 / D6 各跑 10 / 15 / 15 局。专门挑甲层测不到的：模型自己会不会迷路、会不会把 DSL 当笔记本抄、会不会放宽 targets。
- **裁判**：独立实例，看不到作者代码，只判可机器判定的项：目标卡逐字、漂移（最终 brief 和首句硬约束逐条比对）、伪用户消息、重复扣费、工具失败率、轮数、上下文字节。
- **回灌**：每种新失败模式沉淀成一个 `__invariants__` 回归样本（输入来自真实失败局，期望来自首句原话，不来自实现），然后派修复切片。

### L3 品味产线（D1 起并行，D4 接进产线）

AGENTS.md：「谁把品味做成产线，谁才有下一程」。这一条就是落地。

- **D1–D3 采集与拆解**：每条产线收 **12 部**前人作品，共约 **150 部**，逐镜拆成镜头语法卡，**约 1,500 张**：镜长、景别、构图（主体位置/留白）、运镜、转场类型和时点、字幕层级（字号/位置/出入方式）、色盘、节拍对齐。每张都要附出处 URL 和时间码，没出处的不收。
  - 分工：看帧走 `read-image`（Gemini 通道，不吃 grok 池）；grok 只负责找片、抽帧调度和整理成卡。
- **D2 暴君选锚（全周唯一一次审美交互，≤20 分钟）**：每条产线给 3 组明显不同的风格簇，每簇 4 张关键帧拼图。暴君每条产线点 1–2 簇。点中的就是这条产线的「品味锚」。
- **D3–D4 接线**：
  - 配方的 `guidance` 改成从锚点语法卡生成（镜长分布、转场表、字幕规格），不再写形容词。
  - critic rubric 改成「与锚点的量化偏差」：镜长分布 KL、转场类型命中、字幕安全区和字号层级、黑帧/冻结帧、响度。分数只用来筛选，不当审美裁决。
  - 在 `research` 节点里，研究 agent 先去品味库检索 3 部最近邻作品，再写分镜（研究先行，有痕迹可查）。
- **双侧判准**：语法卡 ≥1,200 张，13 条产线每条 ≥80 张；不许为凑数收低质量作品，由一个独立实例抽 10% 复核出处和标注。

### L4 交出去的还能改（D3–D5）

「只交一个死文件，等于没交。」

- `export` 节点除 mp4 外，增加两种产物：**剪映草稿包**（`draft_content.json`＋素材目录，zip）和 **FCPXML 1.10**。时间线、字幕轨、音轨、镜头名和工程图节点一一对应。
  - 第一动作：抓开源实现读源码（pyJianYingDraft 一类的剪映草稿库、OpenTimelineIO 的 FCPXML adapter），先读 LICENSE 再动手。照它的结构做，不自己猜格式。

## 7. grok 派工协议（每片 spec 必含）

1. **预期分钟数**：超过 2 倍就 TaskStop，改 spec 重派。
2. **必读记忆**：`~/.claude/memory/MEMORY.md`＋对应 pack＋2–5 篇 note（用 `mem find` 取真档名）。记忆和现场冲突时以现场为准，并回报冲突。
3. **独占文件清单**：一片 ≤1 个主文件，diff ≤300 行。
4. **配方**：部署、测试、远端命令直接贴可复制粘贴的原文。权威测试门是 `bash deploy-staging/vps-tools/run-tests.sh`，测试路径一律用 `import.meta.dir`。
5. **双侧判准＋不可牺牲清单**：上限必须配下限。
6. **导入者审计**：新模块在测试以外必须有真实 import。零消费者就不算交付。
7. **作者 ≠ Hacker ≠ 验收者**：Hacker 只拿真实输入和首句原话。小片（diff <80 行）可以把 Hack 和验收并成一片，省额度。
8. **付费**：上游 key 不下发。生成提交只能写「待 orchestrator 执行」。
9. **并发**：常态 3–4 路；完工一路，验收后立刻补派一路。
10. **同一错误**：重试 2 次没过就停，回报事实。
11. **省池子**：spec 直接贴要改的行号和片段，不让 worker 从头探索代码库。上下文超过 200K 单价翻倍，单片会话超过 150K 就收尾重派。
