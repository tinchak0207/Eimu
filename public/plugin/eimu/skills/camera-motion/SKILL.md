# 运镜与镜头运动

## 事实边界

Eimu 的 MCP 有 23 个工具，但没有摄影机轨道参数、没有关键帧曲线、没有预置运镜库的调用入口。运镜只能写进 `generate_video` 的 prompt 文本里，节奏靠 `duration_seconds`，画幅靠 `size`。不要向用户承诺「套用某个运镜预置」或「调用运镜参数 API」——我们做不到。（画布产线的读取/写入/回滚另有工具，但那不是运镜预置库。）

## 提示词四段式

每次都按这四段写，顺序固定：

1. **镜别**：大远景 / 全景 / 中景 / 近景 / 特写。
2. **机位与角度**：平视 / 俯拍 / 仰拍 / 过肩 / 主观视角；机位在人物的哪一侧。
3. **运动**：推进(track in) / 拉远(track out) / 摇镜(pan) / 平移(truck) / 跟随(follow) / 环绕(orbit) / 升降(crane) / 手持(handheld)。写清方向、幅度与快慢，例如「缓慢右摇约 30 度」「匀速推进到近景」。
4. **落点**：运动停止时画面停在哪（停在面部特写 / 停在招牌上），以及这段时间里主体在做什么。

## 步骤

1. `get_quota` 看余额，`list_models` 取视频模型与 `x_coins_per_second`，先按秒数估出这条镜头的成本再决定要不要试。
2. 若这一镜来自静帧：先用 `generate_image` 出关键帧（需要参考就带 `reference_images`，最多 5 张）。静帧是运动的起点，构图要在运动方向上留出余量。
3. `generate_video` 提交：prompt = 四段式；`duration_seconds` 按运动幅度估——缓推 3-5 秒、环绕 5-8 秒、快速甩镜 1-2 秒；`size` 取项目画幅（如 `1920x1080` 或 `16:9`）；需要现场声就开 `generate_audio`。
4. `get_result`（`kind: "video"`, `id` 为返回 id）轮询到终态。
5. 播放确认三件事：方向对不对、中途有没有莫名变向、主体有没有跑出画。静态帧看不出来，必须看动起来的成片。
6. 只有确实不符时才重跑，并把修正写进同一段（例如把「自右向左」改成「自左向右」），不要整段重写——整段重写会让镜别、光线、人物调度一起漂移，等于重做一条。
7. 镜头之间的运镜要有变化：连续三镜不要用同一个运动方向与速度；相邻镜头反向运动能强化衔接。
8. 交付时逐镜给出：prompt 原文、时长、成片链接、重跑次数与原因（若有）。需要更高分辨率时对关键帧用 `upscale`，不要试图放大已生成的视频。
