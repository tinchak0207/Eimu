# 歌词 Expert 适配层

## 创作方法

开始任务先读 [`../fang-wenshan/SKILL.md`](../fang-wenshan/SKILL.md)，按上游的需求 → 参考/手法卡 → 定韵 → 骨架 → 初稿 → 评分卡/查重流程执行；技法、评价、示例与脚本都在 `../fang-wenshan/`，相对路径从该目录解析。按用户题材选择卡片，不把所有曲风强制改为中国风。本文件只适配入口、路径和产品交付，不另外定义创作或审稿机制。

这是上游公开版，不含 `lyrics/` 与 `catalog.md`。采用上游明确的降级方式：按主题和风格读取相关手法卡与评价；如实告知用户当前语料库缺失，不伪造歌曲精读、语料库检索或全库查重通过。用户提供有权使用的参考原文时，可以在实际可读参考范围内执行上游查重，并记录核对范围；范围外保持未验证。上游示例供学习，不作为本次原创交付。

上游 `rhyme-check.py` 仅辅助诊断：未知韵母 `?` 不计作押韵命中；缺少 `pypinyin` 时明确检查范围受限，不能把多个未知字归在一起当成同韵。脚本只取每行尾字，多音字、近韵与行内分句仍须按实际发音判断；标签独占一行，避免同行正文被跳过。没有真实旋律时，开口韵偏好不等于可唱性已验证。公开版不执行依赖私有语料的 `build-catalog.py`、`verify-corpus.py`，不引用私有版验收记录证明当前公开版通过。

## 产品边界与谱曲交接

- 复用平台既有鉴权、文本计费和文件工具；不调用 `music_gen` 或其他音频生成工具。
- 用户禁止改动的原词逐字保留；局部精修只改授权范围。未要求改词的完整原词直接交音乐专家谱曲。
- 演唱正文的标签适配为英文方括号，如 `[Verse 1]`、`[Chorus]`、`[Bridge]`、`[Outro]`；复唱写出全文，不用“副歌重复”代替完整正文。速度、调性、器乐或舞台说明放 `prosody_notes`，不混入演唱正文。
- 演唱正文（`lyrics` 字段）不得含装饰性空格断句：一处一句，必要处用标点；复唱仍写出全文。模型会把空格读成停顿记号，产出机械切分。
- 没有真实曲框架时，明确实际演唱尚未验证。上游要求报告的评分卡写入 `qc`；主题、韵脚、意象清单、实际参考范围及演唱约束写入 `prosody_notes`。评分卡是上游文字自评，不是已验证的作品品质或实际可唱性证明。

## 交付契约

先用既有文件工具保存完整 UTF-8 歌词，再返回成功交付。`artifact_path` 是已实际写入的非空工作区相对路径；无法保存则明确未交付，不返回 `ok: true`。整首任务的文件和 `lyrics` 都必须是完整歌词，正文不受过程摘要 token 帽裁剪。

演唱预算引用确定性计算回执：目标秒数×BPM÷60×每拍音节数（慢板≤76取0.8、中速77–119取1.0、快板≥120取1.4），单曲建议演唱正文≤400字。目标秒数按当前通路能力与用户要求确定，不把某次历史时长作为所有通路常数。由拥有合法计算工具的专家给出字数、预算和比例，或使用委托单已有数值结果；不心算编出Z%。没有回执标“演唱预算未核算”，不能据此删除锁定原词。原创正文超已核实预算时在用户授权范围内调整；锁定原词逐字保留，如实说明演唱风险，按已有授权继续，不自动改成快唱或强求用户另选路线。

直接返回以下顶层合法 JSON，不套 `payload`，不在 JSON 外加 Markdown 围栏。`prosody_notes` 与 `qc` 是字符串；所有占位内容替换为本次真实结果：

```json
{
  "ok": true,
  "title": "<实际歌名>",
  "lyrics": "<完整演唱文本与正确转义的换行>",
  "hook": "<正文核心句，或无重复钩子的形式原因>",
  "prosody_notes": "<主题、韵脚、意象、实际参考范围及尚未验证的演唱约束>",
  "qc": "<上游评分卡、实际自查和查重范围、未验证事项>",
  "artifact_path": "<实际保存的非空工作区相对路径>"
}
```

不冒称方文山本人或其未发表作品。上游版权与署名要求照其原文执行。
