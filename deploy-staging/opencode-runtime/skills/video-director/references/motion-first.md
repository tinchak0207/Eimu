# 动态优先（Motion-First）

本档先于 [motion.md](motion.md) 读取：先决定「这一镜里什么在变、怎么变」，再决定机位怎么走。运镜是动作的放大器，不是动作的替代品。

## 1. 物理事实：视频 = 帧间变化

- 视频是被渲染出来的帧序列。观众看到的「动」，来自相邻帧之间画面内容的实际变化；没有任何内容变化，再花哨的运镜也只是同一张图被放大。
- 首帧条件越强、静态描述越多，模型越倾向把输入图原样保留：I2V 单张静帧 + 六槽静态描述的实际输出，通常就是轻微呼吸、头发飘动和缓慢推近——这就是成片像 PPT 的物理原因。
- 结论（硬规则）：**动作镜头不能以单张静帧作为唯一条件**。首帧可以用来定外观与构图，但不能承担「这一镜发生什么」的全部信息；动作必须由 beats 时间线或 3D 预演显式给出。

## 2. 镜头合同（与 gateway schema 对齐）

一个影片 shot 至少要有可观察的状态变化，结构固定为：

```
state_change.from  →  beats[]  →  state_change.to
                      （at_seconds?, action, environment_change?）
```

| 字段 | 必填性 | 写什么 | 反例 |
|---|---|---|---|
| `state_change.from` | 与 `to` 成对或由 beats 兜底 | 镜头开始时的可见状态（人物姿态/位置/环境） | 「一个男人站着」 |
| `beats[]` | 至少一条非空 `action`，或 state_change 两端齐备 | 按时间顺序的动作事件，每条是**可见变化** | 「他缓缓抬头」 |
| `beats[].at_seconds` | 可选，写了必须严格递增且 ≤ 镜头时长 | 事件发生的秒点，用来给剪辑和触发机位定锚 | 三个 beat 全写 0 |
| `beats[].environment_change` | 可选，用于镜内环境变化 | 这一 beat 期间环境发生的可见变化 | 「气氛变紧张」 |
| `state_change.to` | 与 `from` 成对或由 beats 兜底 | 镜头结束时的可见状态，下一镜据此交接 | 「结束了」 |
| `environment_change` | 每镜至少一项（本档验收口径） | 整镜层面的环境变化（天气/光线/人群/烟尘） | 「环境不变」 |

- 每镜至少一次可见状态变化；只有静态画面 + 六槽会被 `validateMotionContract` 拒收（invalid_shot）。
- `environment_change` 每镜至少一项：不是每镜都要换场景，但每镜都要有环境层面的可观察变化（光变、风、尘、人流、门开、水动）。
- 字段写法与编译细节以 `deploy-staging/gateway/video-prompt-schema.ts` 为准；本档只讲创作口径。

## 3. 动作 beat 怎么写

一条合格 beat = **物理动词 + 身体机制 + 对象/环境交互 + 秒点**。四样缺一样，模型就有空间把它退化成微动。

反例（全是形容词与情绪，没有可渲染的身体动作）：

```
人物缓缓抬头，眼神坚定，气氛变得紧张。
```

正例（每条 beat 都是一个可见状态跃迁）：

```
state_change: { from: "屈膝压低重心，刀背贴地，草叶静止", to: "半跪落地，敌群被冲击波推开，花瓣漫天" }
beats: [
  { at_seconds: 0.0, action: "压低重心起步冲刺，脚掌蹬地，草叶向两侧分开", environment_change: "草叶被蹬起，尘土扬起" },
  { at_seconds: 1.6, action: "跃起挥刀，手臂从右后方向左前方划过，刀刃带出弧线", environment_change: "花瓣被气流卷起成旋" },
  { at_seconds: 3.2, action: "落地滑行半步，膝盖弯曲缓冲，刀尖点地", environment_change: "冲击波把敌群推开，地面尘土成环" }
]
```

写法纪律：

- 用「谁 + 做什么 + 带动什么」；不写「缓缓」「渐渐」「似乎」这类无法被渲染的副词。
- 动作要带身体机制（重心、蹬地、屈膝、肩胯转动），否则模型只会做头部微动。
- 每 beat 至少一个对象/环境交互（碰到什么、推开什么、激起什么）。
- 秒点只在有剪辑或触发需求时写；不写就按出现顺序叙述，禁止给每个 beat 硬凑相同间隔。
- 一个 beat 只承担一个主动作；连续两个主动作之间要能看见过渡（起步/收势）。

## 4. 3D 预演优先

动作、走位、多人、空间关系镜头，**先预演，再生成**：

1. 用 director-engine 白模（L1，免费）或 Blender（L2）摆出 blocking：人物/道具的位置、朝向、初始与终止姿态。
2. 定机位路径：起点、终点、路径形状、关键转折时刻；多人镜头同时定轴线与屏幕方向。
3. 定动作模板：每个 beat 对应白模里的一段动作，确认动作在空间中真的发生了、没有穿模、没有互相遮挡。
4. 渲染首/中/尾关键帧（必要时加中间帧），作为视频模型的**参考条件**。
5. 把「关键帧 + 运镜路径 + beats 时间线」一起交给视频模型；预演帧不进成片，只用来锁 blocking 与构图。

允许的例外：单人物微表情、产品特写、纯氛围空镜这类不涉及精确几何与走位的镜头，可以直接用首帧 I2V。**涉及人物动作、走位、多人互动、空间关系，一律先预演。**

### 能力闸门（2026-10-20 现场）

开拍前先查**真实工具表**（本席位 live 工具清单），不看 SKILL 宣称，也不看工具文件是否存在：

- 逐个确认 `blender_exec` / `blender_render` / `blender_export_gltf` 是否真的可用；必要时再查桥主机 `command -v blender`。任一不可用 = Blender 路径不成立，禁止调用 blender_*。
- 不可用时按优先级降级：
  1. **director-engine 白模（L1，免费）**：用 `director_*` 工具摆 blocking、定机位路径，渲染首/中/尾关键帧。
  2. **bash + 自建几何 + 光栅渲染**（纯 Python/Node 都行）：自建相机与物体几何，代码算投影后光栅化出图，产出首/中/尾关键帧与 GLB，并写出每帧对应的机位/动作参数。
  3. 只有**完全不做预演**时才允许跳过：交付里明确写「本镜跳过预演，原因 X」。
- 禁止用二维文生图冒充 3D 预演；预演帧必须由真几何/真机位算出，不是二维模型生成的氛围图。
- 禁止伪称 `.blend` 已交付。`.blend` 缺失时在交付里写「.blend 未交付（本席位无 blender）」，预演帧与 GLB 仍算真预演证据。

## 5. T2V 优先

- 没有跨镜一致性刚需的动作镜头，直接 T2V：让模型自己生成运动和场景，比拿一张静帧去「猜动作」自由得多。
- 需要一致性（角色脸、服装、场景）时用参考图，但参考图只锁外观与风格：**不锁构图、不当首帧**。
- 只有在「必须精确复现某个构图/姿态」时才把预演关键帧当首帧条件，同时仍然写全 beats——首帧负责起点，beats 负责过程。

## 6. 场景变换

- 每个场景至少一次环境变化；同一场景内的连续镜头也不要让背景完全静止（光、风、尘、人群、蒸汽、雨）。
- 镜内切镜是合法剪辑手段：用 beats 的 `at_seconds` 表达「第 2 秒切到手的特写」，不必把一镜拍成一条连续运镜。
- 转场要有动作依据：遮挡、甩镜、主体经过前景、门/帘/烟遮住画面，都比纯叠化更像成片。

## 7. 反 PPT 验收

- **全片不得出现「每镜都慢推」**：至少一镜的主体在画面内发生明显位移（人物走过、跃起、转身、物体被抛起）。
- 至少一镜的机位由动作触发（跟拍、甩镜、急推、停下再动），而不是全程匀速。
- 量化验收：交付前用 `video_evidence action=motion` 检查每镜，读 `median_diff`（相邻帧亮度中位差，抗剪辑）与 `static_ratio`（YAVG<1.5 的近静止帧占比）：
  - `verdict=dynamic`：`median_diff ≥ 6` 且 `static_ratio ≤ 0.20`（阈值真源：`lib/video-evidence.ts` 的 `MOTION_THRESHOLDS`）。
  - `verdict=weak`：`median_diff ≥ 3` 但未达 dynamic —— 动作镜头按未达标处理，继续加动作/换预演关键帧；文戏可人工复核后保留。
  - `verdict=static`：`median_diff < 3` —— 该镜必须重做，或如实标注「未达标」，不伪签通过。
  - 参考基线：动作戏参考片 median 12.37 / static_ratio 9.9%；PPT 式成片 median 2.67 / static_ratio 30.0%。单帧、单张美图、总像素差都不能替代这一指标。
- 若当前部署的工具表还没有 `action=motion`（旧发布），用 `action=frames` 取帧后按同一公式自算，并在交付里写明「用替代路径验的、未走 motion action」，不伪签 PASS。
