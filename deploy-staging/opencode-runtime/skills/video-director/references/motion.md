# 按目的选择运动

每次只选任务需要的主运动，不套统一 slow push：

| 叙事作用 | 候选 | 必须写清的可观察变化 |
|---|---|---|
| 阅读动作、细节或克制情绪 | static | 固定机位与焦距，主体动作和停顿 |
| 接近人物、强化关注 | dolly in/out | 摄影机沿场景参照前后位移、遮挡与远近层关系 |
| 跟随行走/奔跑 | tracking/truck | 跟踪对象、左右路径、相对距离、背景经过节奏 |
| 揭示旁侧空间 | pan | 固定机位水平旋转，起止朝向、新信息出现时点 |
| 连接高低层信息 | tilt/pedestal | tilt 是定点俯仰，pedestal 是机位上下移动 |
| 展示人物与空间关系 | orbit/arc | 绕行中心、弧段、轴线与遮挡揭示，避免无理由绕圈 |
| 改变注意范围且保机位 | optical zoom | 焦距变化；不得宣称 dolly 或物理位移视差 |
| 动作冲击后恢复辨识 | rapid pan/handheld | 动作触发、方向、幅度、落点与可读停留 |

几何关系先于镜头数字：先确定主体、固定参照、路线与新信息，再给必要焦距/幅度。多镜保持屏幕运动方向；越轴须明确动机与空间重新建立。图像 reference 是条件，不是下一镜开场已经成功。每镜结尾保留可接续状态或动作，不把每镜都做成定格。

默认用一条 camera.trajectory 描述权威机位路径，movement 标运动类型，timing 只补必要节奏；不为同一路径再造 start/end/keyframes 多份位置描述。用户明确要求的字段与硬约束照样保留；分时控制必须从这条路径推导，缺可靠空间依据或出现方向/位置顺序冲突时，不能编坐标或硬精确保证，改成可执行的简洁方案。

timing 必须保原任务的因果顺序：谁先完成什么、摄影机等到什么条件才启动、之后如何移动。把同一触发条件及先后关系写进最终 shot.prompt，不得用“全程匀速”覆盖先等待后移动；未给定精确秒数时用事件条件，别自行分配秒点。交付前对照原任务检查这些显式约束，不增加第二套路径或位置表。

固定朝向、固定光轴、固定焦距且地标静止的纯横向平移中，静止近景与静止远景在画面里都向摄影机位移的反方向滑动，近景位移更大、更快；例如摄影机向右 truck，门框和远墙都向画面左侧滑动，门框滑得更快。此规则只用于上述纯平移条件，不能因为深度不同就把近远景写成相反方向。orbit/arc 或旋转跟拍包含光轴旋转，没有可靠三维资料时不预测每个地标的左右漂移方向；只描述有据的绕行、瞄准关系和可见揭示。判断机位视差至少选两个静止的场景参照（如门框与远墙），移动的人物、手或手持照片不能单独证明摄影机位移。parallax 是可选可观察描述，没有足够依据就省略，不从运镜名称编造方向。
