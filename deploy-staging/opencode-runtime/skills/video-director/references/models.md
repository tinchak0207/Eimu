# 模型与输入边界

先读实际目录的 model/capabilities/reference 限制与报价；下列是写法参考，不是平台已支持该模式的承诺。不凭模型名宣称最佳，也不导入旧 API 参数。

- **MiniMax H3**：prompt 用官方 Content IR（`.opencode/skills/minimax-h3/content-ir.md`），不走六槽，不套旧 Hailuo 方括号。纯文本、首帧、首尾帧、仅尾帧用三栏；参考素材不是具体帧时用 Ref2VA 六栏。自然语言写动作、幅度、速度；push/pull 是位移，zoom 是机位固定的焦距变化，pan/tilt 是旋转。参考图存在不等于首尾硬锁。参考视频可提供运镜/剪辑/节奏，但 reference generation 不等于编辑已有视频。
- **Runway Gen4.5 I2V 写法参考**：图像负责主体/构图/光照，短 prompt 优先关键 motion，再分主体、环境、机位与速度/时序。图中模糊、扬尘或姿势与静止目标冲突时先修输入，不能只堆负面词。此处不宣称本站提供 Runway。
- **Seedance**：把空间层与时间层分开，参考逐项说明来源及作用；用事件顺序组织动作，不把精确秒点当保证。2.0 指南不能冒充 2.5 完整能力说明。
- **Agnes Video 2.5 Flash（免费兜底）**：平台自有免费额度视频档（model id `agnes-video-2.5-flash`），上游成本 ¥0，是付费视频渠道（MiniMax H3／Seedance／miaowu）余额断或全断时的**最后手段**。免费档队列与限速较慢，只有 480p/720p、5/10 秒，**不支援参考图（无图生视频）**，画质与可控性低于付费档——只在付费档不可用时才用它，**不因为「免费」就默认选它**；提交前照常按目录能力与报价核对档位。
- **复杂运动**：文本约束可引导，不等于 CameraCtrl 的 K/c2w/Plücker、MotionCtrl 每帧 RT 或 native pose 张量。没有平台原生接口就不得宣称精确轨迹锁定。

## 分辨率档位与高清交付

目录里每个模型都带 `resolutions` 与分档单价（`video_quote` 的 `coins_per_second` 按档给值）。选档位只看两件事：用户要的交付规格，和这个模型报出的真实档位——不要凭模型名气假设它出得了高清。

- **MiniMax H3 高清档走平台自动超分**：H3 本身只出 768P；平台把目录里的 `1080p`／`2k`／`4k` 解释成「H3 出 768P → auto-hd 超分」两段链路，网关自己跑完两段、只回一个最终成片 URL。**导演侧填一个 `resolution` 就结束**：不要拆成「先要 720p，再去别的工具超分」——视频没有独立超分工具，`image_upscale` 只吃图片。分两步做只会白花一笔 H3 生成费，或者根本做不出来。
- **2K／4K 是正常可选项，不是要请示的高价特权**：用户说「2K 电影」「4K 交付」就直接填该档，按目录分档价如实报给他，不要自作主张降档交付，也不要为省钱先出 720p 再说「差不多」。反过来，用户没提档位时默认 720p，不擅自加价。
- **低清只用于迭代**：480p／720p 试拍是为了验构图和动作，定稿后按目标档**重新生成**一次，不是把试拍片拿去放大。把试拍片当终稿交付＝低清冒充高清。
- **交付前核对真实尺寸**：回执/成片探针里的实际像素要和 `resolution` 对得上（2K ≈ 2560×1440 一带，按画幅吸附）。平台在超分未完成时按失败退款，不会回低清；但你自己仍要看一眼成片真实尺寸再说「高清已交付」。
- **模型到不了该档就明说**：目录 `resolutions` 里没有 2k/4k 的模型（例如免费兜底档 Agnes 只有 480p/720p），不许用超分话术掩盖，直接说这个档位到不了，给能到的模型或从原生支持该档的模型里选。

独立审阅以真实原片及时间序列对照真实生成 input；清楚区分固定镜头主体动、旋转、物理位移和仅放大。样本只有帧序列时不能宣称连续播放，不能凭全帧像素差判定 dolly。
