DeepSeek Harness 深度指南

本篇基于 v0.1.0-rc.5 源码逐层讲解：你拿到的压缩包里面每一块是什么、系统按什么顺序组合配置、 CLI 有哪些模式、权限沙箱怎么工作、Agent 能用哪些工具，以及如何不改源码就扩展它。 适合已经把快速上手跑通、想真正理解和定制 Harness 的读者。

01

源码目录导览

解压后根目录的关键部分：

deepseek-harness/
├─ apps/
│  ├─ cli/        dsh 命令入口（src/args.ts 命令语法，src/bin.ts 加载运行器）
│  └─ web/        浏览器 Web 前端源码（Vite 构建）
├─ packages/      核心包（全部是插件，见下）
│  ├─ bundle/     base / web-app / headless 三个组合包 = profile 模板
│  ├─ llm/        LLM 适配器（llm-deepseek、llm-pi-ai 等）
│  ├─ core/       会话日志、工具注册、agent 循环、作用域
│  ├─ sandbox/    进程沙箱（read-only / workspace-write / danger-full-access）
│  ├─ credentials/  凭据存储（.credentials.yaml，只写）
│  ├─ settings/   设置文档与解析
│  ├─ shell/      命令执行 seam
│  ├─ subagent/   子代理提供方
│  └─ tool-*/     面向模型的工具包（bash、fs、search、terminal、web…）
├─ native/        Landlock（Linux）沙箱原生实现
├─ examples/      acp-agent / headless-agent / jsonrpc-agent / mcp-memory 等示例
└─ docs/          官方文档（user/guide 有中文版）

最重要的设计事实：产品的每一部分都是插件——模型适配器、工具注册、会话日志、 Agent 循环本身全部是插件，可以被配置替换，不存在需要打补丁的特权内核。这也是为什么改配置就能改行为，不一定需要改源码。命令语法在 apps/cli/src/args.ts，运行器加载在 apps/cli/src/bin.ts； 组合包模板在 packages/bundle/。

三个组合包：@deepseek-ai/dsh-base（每个 profile 的第一层：模型、工具、持久化、沙箱、权限、设置、凭据、遥测）、@deepseek-ai/dsh-web-app（加浏览器应用）、@deepseek-ai/dsh-headless（一次性运行器，无服务器）。

02

配置体系：profile / bundle / patch

运行中的 dsh 是一棵插件树，由启动时按序叠加的配置层组成。理解这套 层叠是定制 Harness 的钥匙：

配置树叠加顺序（后层优先，后者覆盖前者）：
1. dsh.profile.bundles 里列出的各组合包 patch
2. profile 自己的 cordis.patch.yml
3. home 级 $DSH_HOME/cordis.patch.yml（机器级偏好，所有 profile 共享）
4. 命令行 --patch <file> 覆盖层（按 argv 顺序）

关键规则：patch 按行 id 定位，替换整行的 config 值，而不是合并键； 它也可以插入新行。所以查看你的机器实际生效的配置树，是定制前的第一步：

dsh --profile web --dump-config        # 看完整生效配置树（注释标注每行来自哪个文件）
dsh --profile web --dump-default-config  # 只看组合包自带层，不含用户 patch

dump 出来的任何一行，都可以由你自己的 patch 替换。想临时加一个覆盖层而不改任何文件：

dsh web --patch ./extra.cordis.yml

Harness home（$DSH_HOME）

默认是 ~/.dsh（可用 DSH_HOME 改路径），里面：

~/.dsh/
├─ settings.yaml           设置文档（模型模态、通用设置等）
├─ .credentials.yaml       凭据（只写：保存后只回脱敏描述符，永不返回明文）
├─ cordis.patch.yml        home 级 patch 层（所有 profile 共享）
└─ profiles/
   ├─ web/                  web profile（package.json + dsh.profile + cordis.patch.yml）
   ├─ headless/             headless profile
   └─ node_modules/         dsh 维护的符号链接后备目录

提供方凭据按顺序解析：继承的环境变量 → $DSH_HOME/.credentials.yaml→ 调用目录的 .env → $DSH_HOME/.env。 凭据由受管文档保存，不会物化进 process.env。

03

CLI 命令全集

dsh web                                   # 启动 Web UI（--profile web 的别名）
dsh web --port 8080                       # Web 应用参数：端口
dsh web --host 127.0.0.1  --trusted-host x --trusted-host y
dsh web --help                            # 显示 Web 应用的帮助（不启动）
dsh --profile headless "run the tests"    # 一次性任务：跑完打印结果退出
dsh --profile headless --dump-config      # 只查配置不启动
dsh plugin --profile tui add <package>    # 给 profile 装插件（转发给 pnpm）
dsh plugin --profile tui remove <package>
dsh --help                                # 启动器自己的帮助
  • 启动器 flag 必须写在最前面：启动器只解析自己的 flag，第一个无法识别的 token 之后的内容原样交给应用。所以 --port 属于 web 应用。
  • headless 一次性任务：创建全新持久化会话 → 提交任务 → 等待完全停稳并 flush → 打印最终回答。原因为 completed 时退出码 0，否则 1。 它不开服务器、不占用端口。
  • --host 0.0.0.0 会被拒绝：CLI 有意不支持绑定所有网卡，防止局域网暴露。 要开 LAN 访问请用可重复的 --trusted-host 声明可信主机名。
  • 关闭行为：SIGTERM 优雅退出（退出码 0）；第一次 Ctrl+C 报告 130； 第二次立即强制退出。
04

模型路由与提供商

DeepSeek 官方

设置 → 模型 → DeepSeek 卡片填入 API Key 保存即可，模型路由立即可用、无需重启。密钥只写： 保存后界面永不回显，存储在 $DSH_HOME/.credentials.yaml。

目录提供商（开箱即用的其他家）

选择「添加提供方」，可选取 Anthropic、OpenAI 等，填入密钥即可。注意需要原生凭据的提供商：Bedrock（AWS 凭证+区域）、Vertex（ADC 项目）、Azure（api-version）、Codex（OAuth）， 只填 API Key 字段无法完成配置。

自定义提供商（网关 / 自建 / 兼容端点）

公司网关或任何 OpenAI 兼容端点选「添加自定义提供方」，填：Provider ID（小写，永久， 请求、会话、凭据引用都用它，改不了只能删了重建）、基础 URL、API 协议、API Key，以及至少一个模型。 在「模型目录」点「获取可用模型」会去查 GET /models；没有该接口的服务 就手动输入模型 id。

模型模态：手动录入的模型默认按纯文本对待。视觉模型需要在$DSH_HOME/settings.yaml 给该模型加input: [text, image]；整个路由都支持图片则用defaultInput: [text, image] 一次设置。

# settings.yaml 片段：给自定义网关的一个模型开图片输入
llm-pi-ai:
  providers:
    my-gateway:
      apiKeyEnv: GATEWAY_API_KEY
      api: openai-completions
      baseURL: https://gateway.example/v1
      models:
        - id: vision-preview
          input: [text, image]
05

权限与沙箱

沙箱只有三个模式（都只限制文件操作）：

read-only             只读：不能改任何文件
workspace-write       默认预设：bash 和文件修改仅限当前工作区 + 平台临时目录
danger-full-access    不限制：可以改任何路径文件（高危）

默认的 workspace-write 下：读取、网络访问和进程可见性不受限制；写入被 限制在工作区内。Agent 想越权时会走审批升权链：

read-only → workspace-write → danger-full-access

Web UI 里遇到需要批准的操作会先询问你，批准即按更宽策略重发一次调用。新会话默认 workspace-write；DSH_PERMISSION_MODE 更换进程级后备值； 设置中的「通用」里存的权限影响后续 Web 会话，不改变已打开的会话。

沙箱后端按平台实现：Linux 用 Landlock（含 native/ 下的 landlock-run）或 bubblewrap、 macOS 用 sandbox-exec、Windows 用 ACL restricted-token runner。后端不可用时会拒绝执行而不是放开限制（SANDBOX_UNAVAILABLE）。

想知道会话实际处于什么模式，看 agent 的系统提示词以外的运行时上下文，或直接查dsh --profile web --dump-config 里的 sandbox 相关行。

06

工具系统：Agent 的能力清单

默认组合挂载的模型可见工具（包 → 工具名 → 说明）：工具 schema 由系统提示词组装自动拼接， 你给 Agent 的能力集合完全由配置决定。

文件读写

readwriteeditstr_replace_editorread_image

read-before-write/edit 强制先读后写策略；read_image 需要模型声明 image 模态。

文件搜索

globgrep

打包自带 ripgrep 二进制（@vscode/ripgrep），不需要宿主机装 rg。

命令执行

bashpwsh

Linux 组合下启用 bash、Windows 组合下启用 pwsh（由 harness 按平台自动切换）；bash 支持 run_in_background 后台运行。

持久终端

terminal_openterminal_sendterminal_readterminal_listterminal_closeterminal_signal

可选项，需要 PTY 后端；跨调用保留终端状态。

后台任务

job_listjob_outputjob_kill

统一管理后台 bash 命令、PTY 发送与后台子代理。

委派子代理

subagentsubagent_forksend_messageinterrupt_agentlist_agentsreport

subagent 可后台续跑；subagent_fork 一次性前台运行；report 在子代理内部上报结论。

计划与任务

exit_plan_modetodo_write

计划模式内走用户审批（approve / 继续规划）；todo_write 渲染为界面里的清单。

联网

web_searchweb_fetch

web_search 默认启用（用 DEEPSEEK_API_KEY）；web_fetch 需要 patch 层插入提供方并启用。

交互与扩展

ask_user_questionskilllspralphworkflowcreate_goalschedule_create

skill 加载技能；lsp 需要语言服务器提供方；ralph/workflow 是结构化工作流引擎。

会话查询

session_searchsession_tracesession_event_readsession_event_searchsession_event_trace

只读工具，按调用 agent 的会话做权限校验。

还有两个特殊开关值得知道：极简模式（minimal preset）只组合持久bash 与 str_replace_editor，系统提示词固定为 「You are a helpful software engineer assistant.」——盲盒最小、适合不信任的代码库；DSH_TOOLS_MODE 选择 native / code / both 三种工具呈现模式。

环境变量速查表

变量作用
DSH_HOMEHarness home 目录，默认 ~/.dsh；存放 settings.yaml、.credentials.yaml、profiles/。
DEEPSEEK_API_KEYDeepSeek 官方适配器与 web_search 的凭据。
DEEPSEEK_BASE_URL改用 OpenAI 兼容代理时的端点（不含 /v1 后缀时由适配器拼接）。
DEEPSEEK_SEARCH_BASE_URL自定义搜索端点。

DSH_TELEMETRY_OTLP_URL自定义遥测 collector 地址。
DSH_TELEMETRY_DISABLED任何非空值都是遥测的最终关闭开关。
NODE_USE_ENV_PROXY设为 1 后 Node 遵循 HTTP_PROXY / HTTPS_PROXY 环境代理。
08

插件与二次开发

不改源码的第一种扩展：patch 覆盖。前面说过，dump-config 输出的任何一行都可以 用你的 cordis.patch.yml 替换，或者用--patch extra.cordis.yml 一次性叠加。两个 patch 文件在运行期间都会被 监视，合法变更会事务式热重载。

安装第三方插件：通过 profile 的插件管理器（内部转发给 pnpm）：

dsh plugin --profile tui add github:deepseek-harness/turtle-ui
dsh plugin --profile tui remove turtle-ui
dsh --profile tui

每次成功安装后，系统会按当前依赖状态更新 manifest 的 dsh.profile.bundles， 插件声明了组合包 patch 就会自动进入配置层栈。Git 托管的插件在安装时会跑 prepare 构建脚本， pnpm ≥10 默认阻止——首次 add 会给出 allowBuilds 提示，把提示的键复制进该 profile 的pnpm-workspace.yaml 再重跑即可。

想自己写插件：先读官方入门（仓库 docs/cordis-primer.zh.md），并对照下面的 「新行为挂哪」表（来自架构文档）：

添加模型提供商

在 ctx.llm 上注册适配器

添加 Agent 能力（工具）

在 ctx.tools 注册，schema 自动加入提示词组装

添加 Shell 执行

注册 ctx.shell 后端；本地通过 ctx.subprocess spawn

添加持久终端

注册 ctx.terminals 后端 + dsh-tool-terminal

添加文件系统策略

注册 ctx.fs 提供方，或监听 fs/* 事件

限制进程权限

使用 ctx.sandbox 后端包装 argv

拦截请求 / 工具 / 轮次

agent/* 或 tools/* 事件；agent/turn-stopping 停止轮次

添加模型可见上下文

agent.inject()，落到下一次获准的请求

添加持久会话状态

扩展 SessionEventMap，从日志渲染与回放

添加 UI / 编辑器集成

驱动 ctx.agents 并从 session/event 渲染

一套轮次（turn）的骨架也值得记住：一步 = 一次模型请求 + 它调用的工具；一回合 = 零到多步。 事件是扩展点——会话事件（持久）、Agent 事件（活跃代理）、能力事件（seam 策略）。 修改模型可见的内容必须同步加会话事件，这是运行时不变量（「模型可见即已记录」）。

09

程序化接入（headless / Python SDK）

headless 一次性任务

不依赖浏览器：

dsh --profile headless "run the tests"
dsh --profile headless --patch ./extra.cordis.yml "deploy to staging"

Python SDK

要求 Python 3.10+，平台限 Linux x64 / Linux arm64 / macOS 14+ arm64；运行时由 pip 包自带，不需要系统装 Node.js：

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
python -m venv .venv && . .venv/bin/activate
python -m pip install deepseek-harness-sdk

export DEEPSEEK_API_KEY=sk-your-key-here
# export DEEPSEEK_BASE_URL=http://127.0.0.1:8000/v1   # 走 OpenAI 兼容代理时
# export DSH_MODEL=deepseek-v4-flash
python examples/jsonrpc-agent/minimal.py   --workspace /abs/path/to/workspace   --session-root /abs/path/to/sessions   --session-id example-001   "Inspect the repository and fix the failing tests."

在自己的程序里用同一套 API：

from pathlib import Path
from deepseek_harness import DeepSeekHarness

with DeepSeekHarness(
    provider="deepseek-official",
    model="deepseek-v4-flash",
    max_tokens=49_152,
    cwd="/abs/path/to/workspace",
    session_root="/abs/path/to/sessions",
    cordis="examples/jsonrpc-agent/minimal.cordis.yml",
) as harness:
    result = harness.run(
        "Inspect the repository and fix the failing tests.",
        session_id="example-001",
    )
print(result.final_response)

复用同一个 harness 与 session id 会保留该会话的 Bash 进程（工作目录、导出的变量、shell 函数）；独立任务请用新 session id。会话目录会收到 JSONL 日志，包含组装后的模型请求与工具 调用。

10

安全与隐私

  • 凭据只写：API Key 保存后只保留脱敏描述符，界面与环境变量都不会回显明文。
  • 遥测默认关闭：会话数据留在本地。显式设置 DSH_TELEMETRY_MODE=FULL 才会上报， 且随附配置没有脱敏规则——上报内容可能包含消息文本、工具参数和工作区路径，谨慎开启。
  • MCP 服务器默认不启用：每条 server 命令都是 Agent 沙箱之外的可信可执行代码， 需要 patch 层显式启用。
  • 会话日志是敏感的：日志里包含模型请求与工具调用，不要提交到公开仓库。
  • danger-full-access 只在可信环境用：沙箱不可用时会拒绝执行而不是放开限制， 别为了省事关掉沙箱。

深度排错表

现象原因解决
Node 版本过低 / node -v 报错需要 v22.19+ 或 v24+重装最新的 Node.js LTS，覆盖安装即可
提示 SANDBOX_UNAVAILABLE当前系统没有可用的沙箱后端（Windows 缺 ACL restricted-token runner、Linux 缺 landlock/bubblewrap）升级/安装对应内核支持，或改用 danger-full-access 预设（注意风险）
启动报错提示运行 pnpm run build运行的是源码目录，前端 dist 或 Host 构建产物缺失在仓库根目录执行 pnpm run build 后再运行
dsh web 报 --host 0.0.0.0 用法错误CLI 有意不支持绑定所有网卡默认 127.0.0.1；如需局域网访问用 --trusted-host 声明可信主机
MISSING_CREDENTIAL模型页没有保存密钥设置→模型，给 DeepSeek（或对应提供方）填入 API Key
UNKNOWN_MODEL选中的模型未配置设置→模型选择一个已配置模型
获取可用模型返回 401密钥不对，或端点没有 GET /models 接口检查密钥；没有该接口的服务就手动填模型
图片在发送前被拒绝该模型未声明 image 模态自定义提供方模型加 input: [text, image]；DeepSeek 官方路由本身纯文本
安装插件 add 失败提示 allowBuildspnpm ≥10 默认阻止 prepare 脚本把提示的键复制进该 profile 的 pnpm-workspace.yaml 后重跑
改了 cordis.patch.yml 没生效patch 按 id 替换整行 config，不深度合并确认行 id 与 dump-config 输出一致；改完自动热重载，可查 --dump-config

最后提醒：本仓库处于开发者预览阶段，版本升级可能有破坏性变更。源码自行改动的 部分，升级前记得备份 ~/.dsh 与你的 patch 文件。官方文档与最新源码见 GitHub 仓库 。
